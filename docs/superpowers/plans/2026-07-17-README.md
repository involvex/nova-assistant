## Diagnosis (why the app feels broken today)

| Symptom | Root cause | Key code |
|---------|------------|----------|
| Retab → model reloads; chat feels “new” | On `AppLifecycleState.paused`, `assistant_screen` calls `ModelOrchestrator.releaseIdleResources()`, which nulls `_activeChat` and closes the model. UI bubbles restore from `ChatHistoryService`, but the LiteRT `InferenceChat` history is **not** replayed on next send. | `lib/screens/assistant_screen.dart` ~468–477; `lib/services/model_orchestrator.dart` ~313–415, ~1624–1637 |
| Input capped ~1716 chars (or ~200) | Android Gemma 4 KV = **2048**. Usable = `2048 × 0.6`. Reserve ~800 tokens (system + jinja). Remaining → ~1716 chars. With history/RAG, budget collapses to floor **200**. | `lib/utils/message_limits.dart` |
| Agent answers long, user can’t type long | Same budget: generation length is not the same as **input** KV budget. Caps protect RAM; answers stream until stop / model max. | Orchestrator + LiteRT |
| Large models / LMK on retab | Gemma 4 E2B ~2400 MB disk + GPU RAM. Pause unload + cold reload fights LMK but feels like “new chat”. | `platform_adaptation_service.dart` LMK snackbar |
| GGUF | UI can pick `.gguf`; install/inference **reject**. Stub cites `llamadart` conflict with LiteRtLm. Explicit non-goal in `doc/PLAN-features.md`. | `model_orchestrator.dart` `_processGgufModel` |
| LAN host/stream | No model server. “Monitor” icons = MediaProjection screenshots, not LAN inference. MCP is outbound client only. | Screenshot + MCP services |
| Compact | Extractive rolling summary already exists (`ConversationSummaryService`) and feeds RAG — **not** injected into `InferenceChat` history and **no** manual button / auto KV trigger. | `conversation_summary_service.dart` |
| Adult mode | No content filter layer. Refusals are model/prompt behavior. Easy prefs + system-prompt suffix. | `assistant_role.dart`, settings toggles |

## Global constraints (all plans)

- Flutter >=3.44 / Dart >=3.12; Android min SDK 26; arm64-v8a.
- Prefer on-device inference; no new cloud LLM dependency.
- Conventional commits; `dart format`, `flutter analyze`, `flutter test` before merge.
- Do not reintroduce FGS “warm model forever” without an explicit user setting (see non-goal in `doc/PLAN-features.md`).
- Keep battery-optimization path available for low-RAM devices.

## Suggested execution

Use **subagent-driven-development** per plan file, one plan at a time, starting with session keep-alive.

Do **not** implement these as one mega-PR — each plan file is a separate shippable unit.
